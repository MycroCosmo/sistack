# si-docs

프로그램 목록 / 테이블 정의서 / 화면 기능 TC 결과서를 다룬다. 기본은 읽기 전용 분석이다.
사용자가 승인한 출력 경로에만 새 파일을 만들고 기존 파일·원본 양식은 덮어쓰지 않는다.
실제 DB·운영 서버·외부 API에 접속하지 않는다.

## 준비

- Node.js >=18. 스킬 폴더에서 `npm ci --ignore-scripts`로 승인된 ExcelJS 4.4.0(MIT)의 lock 의존성을 준비한다. 설치가 승인되지 않았으면 목록을 제시하고 멈춘다.
- 실행 파일: `scripts/si-docs.mjs`. 설치 위치 어디서나 절대 경로로 실행할 수 있다. 루트 저장소에 의존하지 않는다.
- 코드/로그 원문을 외부로 보내지 않는다. 표준 JSON과 셀 문자열은 마스킹하며, 사용자 원본 양식 자체에는 별도의 민감정보 검토가 필요하다.
- 프로그램 ID·회사/프로젝트별 규칙은 사용자 설정 파일에서만 읽는다. 화면명은 정적 title/첫 h1의 LIKELY 제안만 허용하고 클래스/SQL 업무명은 추정하지 않는다.

## 순서

1. [프로그램 목록](references/program-list.md) 또는 [테이블 정의서](references/table-spec.md) 규칙으로 표준 JSON을 추출한다.
2. 파일:라인, 원본 리비전·파일 해시, CONFIRMED/LIKELY/UNRESOLVED를 확인한다. 리비전 미확인/작업 트리 변경도 보고한다.
3. 양식이 없으면 기본 양식을 만든다. 실제 양식과 ID 규칙은 사용자 입력이다. 메타데이터/작성일/ID는 sistack-docs.json에 없으면 빈 칸이다.
4. [양식 매핑](references/template-mapping.md)을 따라 헤더 기반 초안을 보여준다. 사용자가 매핑을 확인하기 전 채우지 않는다. 확인한 매핑의 `confirmed`만 true로 바꾼 별도 파일을 사용한다.
5. 지정한 빈 입력 영역에 채운다. 병합·수식·기존 값 충돌은 중단한다. 사용자 원본은 그대로 유지한다.
6. 재읽기 결과와 limitations를 보고한다. 미확인 칸은 빈 값+노란색, 보고서의 셀 위치로 남긴다. 경고·미확인이 있으면 PARTIAL, 재읽기 불일치면 FAIL이다.

출력은 대상 프로젝트 `.sistack/runs/<run-id>/`의 manifest/report/evidence와 xlsx다.
AI의 PASS는 PL/PM 승인이나 고객 검수 완료가 아니다. 소스 위치는 증거 2, 실제 저장·재읽기는 증거 4다. Excel 화면·수식 재계산은 별도 검증이다.

## 제한

- 화면 TC는 [기능 테스트](references/functional-testing.md)의 별도 Node >=20 진입점을 사용한다. 계정·차수·로컬 데이터 보존을 명시 승인받은 경우에만 실행한다. M4 결과를 화면 PASS로 바꾸지 않는다.
- 보존 검사 범위와 경고 조건은 양식 매핑 문서를 확인한다. 차트/피벗/매크로 등을 보존한다고 약속하지 않는다.
- 사용자 양식·식별자는 공개 샘플/보고서/커밋에 포함하지 않는다. 민감정보를 제거한 양식도 실제 사용 전에 사람이 확인한다.
