# M5a 일반 형식 양식 매핑 검토

**상태: 매핑 초안 승인 대기.** 제공 양식은 실제 회사 양식이 아니라 Claude가 공공 SI 일반 형식으로 만든 것이다. 이번 작업은 **현장 검증이 아닌 형식 일반성 검증의 매핑 검토 단계**다. 실제 채우기·왕복 보존 검증은 아직 하지 않았다. M5a 전체 완료 및 M5b 시작으로 판정하지 않는다.

### 한 일

- 새 기본 엑셀에서 AI/자동화 안내 문구를 기본 제외했다. 승인 관련 안내는 별도 report.md에 유지한다. 제공 양식의 문구와 기존 동결/산출물은 변경하지 않았다.
- 엑셀의 Controller/Service는 클래스명.메서드명, SQL은 네임스페이스명.SQL ID로 표시한다. 패키지를 포함한 원래 식별자는 인덱스/표준 JSON에 그대로 남긴다.
- 제공된 두 양식의 시트·단일/병합 헤더·입력 영역·드롭다운·요약 수식을 읽기 전용으로 확인했다. 상세 열 매핑 및 원본 해시 확인은 evals/private/templates/m5a-mapping-draft-v1/에 보관한다. 양식 원문·헤더·상세 매핑은 이 공개 보고나 커밋에 복사하지 않는다.

### 검증

- `npm.cmd test`: **174/174 PASS**, FAIL 0. 독립 설치, 승인 정답의 소스 근거, 스킬 5개 형식 및 공통 복사본 검사 포함.
- 새 표시 규칙 테스트: 변경 전 AI 안내가 포함되어 FAIL 1/1, 변경 후 새 기본 양식 2종의 문구와 채운 공개 테스트베드의 클래스/SQL 표시를 재읽어 PASS 1/1.
- 제공 양식 2개의 읽기 전/후 SHA-256 동일. 입력 영역에 값을 쓰지 않았다. 상세 초안은 Git ignore 확인 완료.

### 결정

- 사용자 지시대로 매핑 제시 단계에서 멈춘다. 프로그램 행을 화면/클래스/SQL별로 분리하는 방식과 기존 HTTP 메서드+URL별 유지 방식을 함께 제시하며 선택을 대신하지 않는다.
- 업무구분·개발자·예정일·완료일·진척률·사용자 ID 등 소스로 확정할 수 없는 값은 빈 칸과 미확인 표시를 제안한다. 현재 일자/0/100을 임의로 채우지 않는다. 사용자 지정 테스터 ID도 추정하지 않는다.
- M5b 양식은 열 매핑 검토만 한다. 1차/2차 결과를 분리하며 기존 1차 덮어쓰기를 허용하지 않는다. 결과/실행 유형의 양식 허용 값과 현재 계약의 차이는 private 초안에 기록했다.

### 남은 문제

- 매핑 초안은 confirmed=false, executable=false인 설계안이다. 현재 CLI의 단일 표준 열 매핑 설정으로 즉시 실행할 수 없다. 사용자 선택 후 복합 열/외부 업무 필드/2단 헤더의 범용 지원이 필요하다.
- 실제 제공 양식의 저장 후 보존/채우기 검증은 하지 않았다. 기존 합성 양식 통과를 이번 양식의 보존 검증으로 대체하지 않는다.
- M5b용 보조 근거 열과 결과 상태 표현의 차이는 승인 전 적용하지 않는다. TC 생성·실행과 양식 열 추가도 하지 않는다.

### 사용자 확인 필요

프로그램 행 구성(종류별 분리 또는 URL 단위 유지)과 두 문서의 매핑 초안을 확인받아야 한다. 사용자 지시와 prompts/M5a.md의 매핑 확인 GATE에 따라 여기서 멈춘다.
