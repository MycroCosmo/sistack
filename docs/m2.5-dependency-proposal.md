# M2.5 의존성·JSP 공존 설정 승인안

**상태: 2026-10-27 사용자 승인.** 아래는 승인받은 변경안 원문이다. 실제 dependency tree는 [비교 결과](evidence/m2.5-dependencies/comparison.json)에 기록했으며 추가 9개 모두 일치했다. 적용·검증 진행 상태는 `docs/decisions.md`와 MILESTONES.md를 따른다.

## 승인 요청 범위

`examples/legacy-board-thymeleaf/`에만 직접 의존성 2개와 아래 전이 의존성을 추가한다. 기존 `examples/legacy-board/`와 루트 Node 의존성은 유지한다. Controller·Service·Mapper·SQL과 반환 뷰 이름을 유지하면서 공통코드 목록은 JSP, 나머지는 Thymeleaf로 렌더링한다.

| 직접 의존성 | 고정 버전 | 라이선스 | 선택 이유 |
|---|---|---|---|
| `org.thymeleaf:thymeleaf-spring5` | `3.1.5.RELEASE` | Apache-2.0 | 현재 공식 Java 8 지원 버전이며 Spring 5 통합 모듈. 기존 Spring 5.3.39·javax 기반 유지 |
| `nz.net.ultraq.thymeleaf:thymeleaf-layout-dialect` | `3.4.0` | Apache-2.0 | 공식 태그 빌드가 Java 8을 대상으로 함. 요청한 `layout:decorate`/`layout:fragment` 지원 |

Thymeleaf [공식 배포 안내](https://www.thymeleaf.org/download.html)는 3.1.5의 Java 8 지원과 spring5 모듈을 명시한다. Maven Central의 [부모 POM](https://repo.maven.apache.org/maven2/org/thymeleaf/thymeleaf-parent/3.1.5.RELEASE/thymeleaf-parent-3.1.5.RELEASE.pom)도 Java 8과 Spring 5.3.39를 선언한다. 기존 테스트베드의 Spring 버전과 일치한다.

Layout Dialect [3.4.0 빌드](https://raw.githubusercontent.com/ultraq/thymeleaf-layout-dialect/3.4.0/thymeleaf-layout-dialect/build.gradle)는 `JavaLanguageVersion.of(8)`을 선언한다. [4.0 릴리스](https://github.com/ultraq/thymeleaf-layout-dialect/releases/tag/4.0.0)는 최소 Java 17로 올렸으므로 이 테스트베드에는 사용하지 않는다. 3.4.0은 Thymeleaf 3.1.3을 선언하므로 3.1.5와의 조합은 승인 후 실제 렌더링으로 확인해야 한다.

## 전이 의존성과 충돌 처리

아래는 공개 POM과 부모 POM을 읽어 산출한 예상 compile/runtime 집합이다. 실제 Maven resolution 결과는 아직 아니다. 기존 의존성 전체를 다시 승인 요청하는 표도 아니다.

| 추가되는 전이 라이브러리 | 선택 버전 | 라이선스 | 근거·역할 |
|---|---|---|---|
| `org.thymeleaf:thymeleaf` | `3.1.5.RELEASE` | Apache-2.0 | spring5 모듈의 템플릿 엔진 |
| `org.attoparser:attoparser` | `2.0.7.RELEASE` | Apache-2.0 | Thymeleaf HTML 파서 |
| `org.unbescape:unbescape` | `1.1.6.RELEASE` | Apache-2.0 | Thymeleaf 이스케이프 처리 |
| `org.slf4j:slf4j-api` | `2.0.17` | MIT | Thymeleaf 부모의 버전. Layout Dialect의 2.0.16과 통일 |
| `org.apache.groovy:groovy` | `4.0.25` | Apache-2.0 | Layout Dialect의 직접 전이 런타임 |
| `nz.net.ultraq.groovy:groovy-extensions` | `2.3.3` | Apache-2.0 | Layout Dialect 내부 확장 |
| `nz.net.ultraq.thymeleaf:thymeleaf-expression-processor` | `3.2.0` | Apache-2.0 | Layout Dialect 식 처리 |

확인한 배포 메타데이터: [spring5 POM](https://repo.maven.apache.org/maven2/org/thymeleaf/thymeleaf-spring5/3.1.5.RELEASE/thymeleaf-spring5-3.1.5.RELEASE.pom), [core POM](https://repo.maven.apache.org/maven2/org/thymeleaf/thymeleaf/3.1.5.RELEASE/thymeleaf-3.1.5.RELEASE.pom), [Layout POM](https://repo.maven.apache.org/maven2/nz/net/ultraq/thymeleaf/thymeleaf-layout-dialect/3.4.0/thymeleaf-layout-dialect-3.4.0.pom), [Groovy POM](https://repo.maven.apache.org/maven2/org/apache/groovy/groovy/4.0.25/groovy-4.0.25.pom), [extensions POM](https://repo.maven.apache.org/maven2/nz/net/ultraq/groovy/groovy-extensions/2.3.3/groovy-extensions-2.3.3.pom), [expression POM](https://repo.maven.apache.org/maven2/nz/net/ultraq/thymeleaf/thymeleaf-expression-processor/3.2.0/thymeleaf-expression-processor-3.2.0.pom), [attoparser POM](https://repo.maven.apache.org/maven2/org/attoparser/attoparser/2.0.7.RELEASE/attoparser-2.0.7.RELEASE.pom), [unbescape POM](https://repo.maven.apache.org/maven2/org/unbescape/unbescape/1.1.6.RELEASE/unbescape-1.1.6.RELEASE.pom), [SLF4J 라이선스](https://github.com/qos-ch/slf4j/blob/v_2.0.17/LICENSE.txt).

- Layout Dialect 경로의 `org.thymeleaf:thymeleaf`를 exclusion 처리해 spring5 경로의 3.1.5만 사용한다. 이 exclusion은 expression-processor가 가져오는 3.1.2 경로에도 적용된다. spring5는 OGNL을 제외하므로 Spring EL 환경에 필요 없는 OGNL·Javassist 유입도 막는다.
- SLF4J API는 새 pom의 dependencyManagement에서 2.0.17로 고정한다. Groovy는 Layout Dialect의 가까운 4.0.25가 선택되고 extensions의 4.0.21·expression의 4.0.14를 대체하는지 dependency tree로 확인한다.
- Groovy POM의 GPars·Ivy·Jansi·XStream은 optional이므로 추가하지 않는다. spring5/core의 provided·optional WebFlux·WebFlow·Jakarta Servlet 등도 추가하지 않는다. 기존 Spring EL·javax Servlet·JSTL·Jackson을 재사용한다.
- 로깅 provider는 이 제안에 추가하지 않는다. 승인 후 provider 부재 경고가 발생하면 기록하며 별도 라이브러리를 임의로 추가하지 않는다.
- [extensions 빌드](https://raw.githubusercontent.com/ultraq/groovy-extensions/2.3.3/build.gradle)는 Java 8 toolchain, [expression 빌드](https://raw.githubusercontent.com/ultraq/thymeleaf-expression-processor/3.2.0/build.gradle)는 Java 8 sourceCompatibility를 선언한다. [SLF4J 부모 POM](https://repo.maven.apache.org/maven2/org/slf4j/slf4j-parent/2.0.17/slf4j-parent-2.0.17.pom)의 jdk.version도 8이다. 이 근거는 전체 조합을 Java 8에서 실행한 증명이 아니다.

## 적용할 pom 변경안

새 테스트베드 pom은 기존 pom을 기반으로 artifactId/finalName/contextPath를 `legacy-board-thymeleaf`로 구분한다. 기존 라이브러리·빌드 플러그인 버전은 유지한다. 아래 두 블록을 추가한다.

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.slf4j</groupId>
            <artifactId>slf4j-api</artifactId>
            <version>2.0.17</version>
        </dependency>
    </dependencies>
</dependencyManagement>
```

기존 `<dependencies>` 안에 추가:

```xml
<dependency>
    <groupId>org.thymeleaf</groupId>
    <artifactId>thymeleaf-spring5</artifactId>
    <version>3.1.5.RELEASE</version>
</dependency>
<dependency>
    <groupId>nz.net.ultraq.thymeleaf</groupId>
    <artifactId>thymeleaf-layout-dialect</artifactId>
    <version>3.4.0</version>
    <exclusions>
        <exclusion>
            <groupId>org.thymeleaf</groupId>
            <artifactId>thymeleaf</artifactId>
        </exclusion>
    </exclusions>
</dependency>
```

## JSP·Thymeleaf 공존 설정안

변경 대상은 새 테스트베드 `src/main/webapp/WEB-INF/spring/dispatcher-servlet.xml`이다. 기존 JSP resolver를 아래 두 resolver 구성으로 바꾼다. [공식 Spring 통합 문서의 resolver 설명](https://www.thymeleaf.org/doc/tutorials/3.1/thymeleafspring.html#views-and-view-resolvers)은 order와 viewNames를 이용한 체인을 설명한다.

| 반환 뷰 | 선택 resolver | order / viewNames | 템플릿 경로 |
|---|---|---|---|
| `board/list`, `board/detail`, `board/form` | Thymeleaf | 1 / `board/*,login,error` | `/WEB-INF/templates/board/*.html` |
| `login`, `error` | Thymeleaf | 동일 | `/WEB-INF/templates/login.html`, `error.html` |
| `code/list` | JSP | 2 / `code/*` | `/WEB-INF/views/code/list.jsp` |

```xml
<bean id="templateResolver"
      class="org.thymeleaf.spring5.templateresolver.SpringResourceTemplateResolver">
    <property name="prefix" value="/WEB-INF/templates/"/>
    <property name="suffix" value=".html"/>
    <property name="templateMode" value="HTML"/>
    <property name="characterEncoding" value="UTF-8"/>
</bean>
<bean id="templateEngine" class="org.thymeleaf.spring5.SpringTemplateEngine">
    <property name="templateResolver" ref="templateResolver"/>
    <property name="additionalDialects">
        <set><bean class="nz.net.ultraq.thymeleaf.layoutdialect.LayoutDialect"/></set>
    </property>
</bean>
<bean class="org.thymeleaf.spring5.view.ThymeleafViewResolver">
    <property name="templateEngine" ref="templateEngine"/>
    <property name="characterEncoding" value="UTF-8"/>
    <property name="order" value="1"/>
    <property name="viewNames" value="board/*,login,error"/>
</bean>
<bean class="org.springframework.web.servlet.view.InternalResourceViewResolver">
    <property name="prefix" value="/WEB-INF/views/"/>
    <property name="suffix" value=".jsp"/>
    <property name="order" value="2"/>
    <property name="viewNames" value="code/*"/>
</bean>
```

Thymeleaf 레이아웃은 `/WEB-INF/templates/layouts/default.html`에 두고 각 화면의 `layout:decorate`와 같은 이름의 `layout:fragment` 본문을 대응시킨다. 공통코드 JSP는 기존 JSP 조각을 유지한다. 반환 뷰 이름은 변경하지 않는다.

게시판 목록에 기존 `/code/listJson.do`를 읽는 요소를 두고 `th:data-url`·`th:attr="data-url=@{...}"` 표기를 사용한다. 외부 JS가 각 실제 요소에서 URL을 읽어 호출하도록 하며 서버 코드는 유지한다. 인덱서는 URL 선언·요소·외부 JS 포함·소비·AJAX 메서드를 한 경로로 확인한다.

리졸버 우선순위·viewNames·prefix/suffix를 근거로 Controller 반환 뷰를 판정하며 판정 불가는 후보와 이유를 붙여 LIKELY로 남긴다. `redirect:`/`forward:`와 JSON 응답은 별도 의미로 취급한다.

## 외부 held-out 준비 범위

- 후보: [Spring PetClinic 공식 저장소](https://github.com/spring-projects/spring-petclinic), Apache-2.0.
- 고정 커밋: `500158f732419217507c7656904b8e6aa1bcc0d6` (`git ls-remote ... HEAD`로 확인).
- [해당 pom](https://github.com/spring-projects/spring-petclinic/blob/500158f732419217507c7656904b8e6aa1bcc0d6/pom.xml): Java 17, Spring Boot 4.1.0, Thymeleaf·Spring Data JPA starter. 로컬 Java 8 테스트베드와 실행 환경을 혼동하지 않는다.
- 저장 위치: `.testbeds/spring-petclinic/`. 기존 `.gitignore`의 `.testbeds/` 규칙 적용. 실제 클론은 이후 동결 단계에서 origin·고정 SHA를 검사하며 수행하고 소스는 커밋하지 않는다.
- 이번에는 메타데이터만 확인했다. 화면·Controller 흐름 선정과 정답 작성은 구현 동결 후 수행한다. 외부 사례는 화면 → Controller 1건만 채점하고 JPA는 제외한다. 삭제 AJAX와 별도 case-id·첫 점수·원본을 보존한다.
- 클론된 프로젝트의 빌드·앱·DB 실행이나 Maven 의존성 설치는 외부 정적 held-out 준비에 필요하지 않다. 수행하지 않은 실행은 명시한다.

## 승인 후 검증 순서

1. 새 테스트베드에서 `mvn dependency:tree -Dverbose`로 위 버전 선택·exclusion·optional 제외를 확인한다. 예상 밖 필수 의존성이나 버전 변경이 나오면 기록하고 승인 범위를 다시 확인한다.
2. `mvn -q test`로 서버 동작과 뷰 설정을 검사한다. Java 8 실행 환경에서 추가 확인하며, JDK 11/17의 release 8 컴파일만으로 Java 8 런타임 성공을 주장하지 않는다.
3. `mvn jetty:run`의 로컬 프로필·127.0.0.1 환경에서 JSP 공통코드와 Thymeleaf 화면, 공통 레이아웃, data URL 외부 JS, 세션·CSRF를 확인한다. 이 학습 단계에서 삭제 held-out의 채점·수집기 튜닝은 수행하지 않는다.
4. 학습 정답 초안 2건 GATE에서 멈춘다. 이후 수집기 구현·회귀 검증을 거쳐 held-out 2건의 흐름 탐색 전 동결한다.

지금은 공개 POM·공식 빌드 설정·기존 소스를 확인한 제안 단계다. 실제 dependency tree·Java 빌드·렌더링·새 eval은 승인 전 미실행이다.
