# 첫 채점 후 차이 검토

> AI의 PASS는 PL/PM 승인이나 고객 검수 완료가 아닙니다.

첫 채점 원본은 `../m3-training-first/`와 커밋 e136ce1에 보존했다. 승인 정답·첫 진단·첫 점수·동결 구현은 변경하지 않고 재채점하지 않았다.

## 04: 설정 블록의 위치 표현 차이

승인 정답은 dispatcher-servlet.xml:9의 interceptor 블록 시작을 가리키고, 첫 진단은 :10의 남아 있는 첫 mapping을 가리켰다. 두 위치는 같은 블록이고 원인 설명도 board 매핑 누락으로 일치하지만 비교기는 정확한 file/line/status를 비교한다. Controller:37은 일치했다. 따라서 누락 1·추가 1, 사례 FAIL을 유지한다.

## 06: 승인 행 번호와 실제 결함 위치 차이

승인 정답 :67은 `getSort()`의 `return sort;`다. 실제 bug.patch가 바꾸는 것은 `getSortColumn()`이고, 패치 후 파일에서 반환문은 :78이다. 첫 진단의 원인 위치 :78은 실제 결함과 대응하지만 승인 정답과 달라 누락 1·추가 1, 사례 FAIL을 유지한다. 정답 행 번호는 사용자 재검토 대상이다.

첫 진단에 포함된 수정안에는 별도 결함도 있었다. diff 생성용 보조 코드가 동일한 `return sort;` 중 첫 번째를 선택해 원인 위치 :78을 기록하면서 제안 hunk는 :67을 가리켰다. 입력 원문 존재만 확인했기 때문에 이 모호함을 잡지 못했다. 첫 산출물은 수정하지 않았다.

`06-sort-sql-proposal.diff`는 메서드 선언까지 문맥에 넣어 :78을 고치는 **후속 제안**이다. 임시 프로젝트에서 `git apply --check`만 수행하고 원본 바이트 불변을 확인했다. 소스 적용·수정 후 앱 테스트·재채점은 하지 않았다. 위치 적중 점수로 수정안의 정확성까지 보증할 수 없다는 제한을 함께 남긴다.
