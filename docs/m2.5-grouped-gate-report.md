### 검증

- `npm.cmd test`: **81/81 PASS**, 기존 승인 정답 8건 PASS·새 초안 3건 DRAFT_SOURCES_VALID, 스킬 형식·공통 복사본 검사 통과. [최종 로그](evidence/m2.5-testbed/grouped-npm-test-final.txt).
- 추가 합성 테스트는 screen의 누락·과탐·상태 오류가 parity에 섞이지 않음, query 제외·HTTP 메서드 유지, 새 관계 종류, 그룹/중복 scope 오류, 공존의 parity 0개, 합산 필드 부재, 저장된 eval 결과 형식을 검증한다. JSP parity 연결의 변형·삭제도 실제 evalTrace 경로에서 차단했다.
- `node scripts/check-eval-compat.mjs 7e133f1 docs/evidence/m2.5-testbed/grouped-eval-regression.json`: 기존 **8/8건 결과 동일**. 보존 v2-final trace와 같은 현재 승인 정답을 두 비교기에 입력해 상태·일치/정답 및 누락·과탐·상태 불일치 배열까지 대조했다. 앱·수집기를 새로 실행한 결과가 아니다.
- `check-expected`는 새 renders/decorates 종류, 그룹 계약·scope, 기준 승인본 해시와 parity 동일성, 실제 소스 해시·근거 라인을 검사한다. [그룹별 정답 계약 대조](evidence/m2.5-testbed/grouped-contract.json).
- 기존 승인 정답·테스트베드·이전 held-out 원본은 변경하지 않았다. `git diff --check` 통과.

### 결정

parity/screen은 정답의 그룹이며 실제 그래프의 연결 종류와 섞지 않는다. 그룹을 지정한 사례는 두 점수를 각각 출력하고 합산 수치 필드를 제공하지 않는다. 기존 8건은 그룹 없는 계약과 점수 형식을 유지한다.

JSP 공존은 검색·등록과 무관하므로 `legacy-board-thymeleaf-coexist`의 screen renders 1개로 검증한다. 수집기 구현 이후 보고서에서도 이 세 사례를 각각 표시한다.

### 남은 문제

- 이번 작업은 채점 계약·비교기와 초안 구조 변경이다. Thymeleaf 수집기·새 학습 eval은 아직 실행하지 않아 screen 일치 점수를 보고하지 않는다.
- checkExistence·Thymeleaf 3.0 분석 합성 검증은 수집기 구현 단계다. Java 8 런타임 BLOCKED와 3.1.5 렌더링 기준은 이전 보고와 같다.
- held-out 2건의 탐색·정답 작성·채점은 시작하지 않았다. 첫 점수 보존 규칙은 유지한다.
