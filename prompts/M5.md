# M5 — si-docs (SI 고유)

## 2026-10-28 범위 조정 — 이 절이 아래 기존 초안보다 우선한다

M5는 **M5a(프로그램 목록·테이블 정의서)**와 **M5b(화면 TC 결과서)**로 나눈다. 실행 지시는 각각 [M5a.md](M5a.md), [M5b.md](M5b.md)를 따른다. 이 파일의 아래 본문은 범위 조정 전 설계 참고이며, 문서 3종을 한 번에 구현하거나 M4 JUnit 결과를 화면 TC 결과로 직접 옮기는 지시로 사용하지 않는다.

- M5a는 기존 추출 JSON → 사용자 양식 매핑 → xlsx 채우기 방식의 문서 2종이다.
- M5b의 단위테스트는 한국 SI의 **화면/프로그램 단위 기능 테스트**다. 인벤토리 자동 생성 → TC 1:1 대조 → AUTO-API/AUTO-UI/SKIP 실행 → 증거와 결과서가 범위다. JUnit은 서버 로직 검증 근거 보조 열이다.
- test-scenario-v2는 현장 규칙 참고 자료다. 원문·회사/프로젝트 식별자·현장 파일명·계정 예시를 저장소에 복사하지 않고 일반화한 규칙만 쓴다. 경로 미확인 시 읽었다고 보고하지 않는다.
- xlsx 라이브러리와 Playwright Node의 후보·고정 버전·라이선스·유지보수/Node 호환성·설치된 브라우저 사용 방식을 비교해 기록한다. **[GATE] 의존성 전체를 한 번에 승인 요청하고 멈춘다.** 승인 전 설치·package/lock 변경·브라우저 다운로드·구현을 하지 않는다.
- 공통 원칙은 원본 양식/1차 결과 보존, 모르는 값 미확인 표시, 실행한 범위만 보고, 개인정보·세션·비밀값 마스킹이다.
- M5a 완료 후 M5b를 진행한다. 각 단계의 실제 양식 GATE와 실행 차수 확인 규칙을 따른다.

## 범위 조정 전 초안 (이력)

`AGENTS.md`의 규칙을 따른다. 선행 조건: M1, M4 완료 기준 충족 (M4의 `test-results.json`을 입력으로 쓴다).

## 목표

코드와 테스트 결과에서 SI 산출물을 만들어 **사용자가 가진 양식(xlsx)에 채우는** 스킬을 만든다.

pstack에는 대응하는 스킬이 없다. pstack은 "최고의 스펙은 코드"라는 입장이지만, 한국 SI에서는 문서가 계약 산출물이고 검수가 문서로 진행된다. SIStack은 이 문서를 **코드에서 뽑아내서** 개발자가 손으로 옮겨 적는 시간을 없애는 것을 목표로 한다.

## v0.1 지원 범위

| 문서 | 입력 | 비고 |
|---|---|---|
| 프로그램 목록 | 인덱스 (화면·URL·Controller·Service·Mapper) | 프로그램 ID 체계는 사용자 규칙을 받는다 |
| 테이블 정의서 | 저장소의 DDL 스크립트, 또는 사용자가 제공한 DB 메타데이터 CSV | **DB에 직접 접속하지 않는다** |
| 단위테스트 결과서 | `test-results.json` (M4) | 테스트 이름이 업무 표현이어야 쓸 만하다 |

- 출력 형식은 **xlsx만** 지원한다. docx, HWP/HWPX는 v0.2 검토 대상으로 `docs/`에 기록만 한다.
- xlsx 처리 라이브러리를 추가해야 하면 후보의 라이선스·유지보수 상태를 비교해 `docs/decisions.md`에 기록하고 승인을 받는다.

## 스킬 구성

```text
skills/si-docs/
├── SKILL.md
├── references/
│   ├── program-list.md        # 열 정의, 프로그램 유형 분류 규칙
│   ├── table-spec.md          # DDL 파싱 규칙 (Oracle/PostgreSQL/Tibero 차이)
│   ├── unit-test-report.md
│   └── template-mapping.md    # 사용자 양식 매핑 파일 작성법
├── assets/
│   └── templates/             # 기본 양식 3종 (스크립트로 생성)
└── scripts/
    ├── extract-program-list.mjs
    ├── extract-table-spec.mjs
    ├── extract-test-report.mjs
    ├── fill-template.mjs      # 추출 데이터 + 매핑 → xlsx
    └── lib/
```

## 핵심 설계: 추출과 채우기를 분리

1. **추출** — 각 `extract-*` 스크립트가 표준 JSON을 만든다 (`schemas/docs/*.schema.json`). 이 JSON이 진실의 원천이다.
2. **채우기** — `fill-template`이 표준 JSON을 양식에 채운다. 양식은 매핑 파일로 설명한다.

매핑 파일 예 (`sistack-docs.json`):

```json
{
  "program-list": {
    "template": "./양식/프로그램목록.xlsx",
    "sheet": "프로그램목록",
    "header_row": 3,
    "start_row": 4,
    "columns": {
      "B": "program_id",
      "C": "program_name",
      "D": "type",
      "E": "url",
      "F": "source_path"
    },
    "id_rule": "BRD-{type_code}-{seq:3}",
    "fixed": { "H": "개발완료" }
  }
}
```

- 사용자 양식이 없으면 `assets/templates/`의 기본 양식을 쓴다.
- 매핑 파일이 없으면 양식의 헤더 행을 읽어 매핑 초안을 제안하고, **초안을 보여준 뒤** 채운다 (헤더명 → 필드 추정은 틀릴 수 있다).
- 병합 셀, 서식, 수식, 다른 시트는 보존한다. 원본 양식은 절대 덮어쓰지 않고 새 파일로 저장한다.

## SKILL.md 요구사항

**description 예시:** "코드와 테스트 결과로 SI 산출물을 엑셀 양식에 채워 만든다. '프로그램 목록 만들어 줘', '테이블 정의서 뽑아 줘', '단위테스트 결과서 작성해 줘' 같은 요청에 사용. 회사 양식(xlsx)을 주면 그 양식에 맞춰 채운다."

**절차**
1. 문서 종류와 양식 확인 (양식 경로가 없으면 기본 양식 사용을 밝히고 진행)
2. 필요한 입력 확보 (인덱스, DDL/메타데이터 CSV, test-results.json). 없으면 무엇이 필요한지 알려주고 BLOCKED
3. 추출 → 표준 JSON
4. 매핑 확인 → 채우기
5. 검증: 생성된 파일을 다시 읽어 행 수·필수 열 채움 여부·빈 칸 목록 확인
6. 보고

**채울 수 없는 칸 처리**
- 코드에서 확인할 수 없는 값(작성자, 검수자, 업무 설명 등)은 **비워두고** 셀을 표시(배경색 또는 메모)한다.
- 보고서에 빈 칸 목록과 채우려면 무엇이 필요한지 적는다.
- 그럴듯한 값을 지어내지 않는다. "프로그램 설명"을 메서드명에서 추정해 채우는 경우 `LIKELY`로 표시하고 사용자가 확인하도록 별도 열 또는 메모로 남긴다.

**금지**
- 원본 양식 덮어쓰기
- DB 직접 접속
- 실행하지 않은 테스트를 결과서에 "통과"로 기록 (`test-results.json`에 없는 테스트는 쓰지 않는다)
- 개인정보가 포함된 테스트 데이터·실패 메시지를 마스킹 없이 기록

## 검증

1. legacy-board로 기본 양식 3종 생성
2. 생성된 xlsx를 다시 읽어 내용 검증하는 테스트 (`npm test`에 포함)
3. 서식 보존 테스트: 병합 셀·서식·수식이 있는 테스트 양식을 만들어 채운 뒤 보존 여부 확인
4. 매핑 없는 양식에서 헤더 기반 매핑 초안 생성 확인

## [GATE] 실제 양식 검증

기본 양식 3종과 매핑 기능을 만든 뒤 **멈추고 보고한다.** 사용자는 실무에서 써본 산출물 양식 1개(민감정보 제거)를 `evals/private/templates/`에 넣는다.

승인 후 그 양식으로 매핑 → 채우기를 수행하고, 매핑 파일을 얼마나 손으로 고쳐야 했는지, 보존 안 된 서식이 있는지 보고한다. 양식 내용은 보고서에 인용하지 않는다.
