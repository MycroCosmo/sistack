## SKILL.md 요구사항

**frontmatter**
- `name: si-trace`
- `description`: 한국어. 무엇을 하는지 + 활성화 상황. 예: "JSP 화면, 버튼, URL, Controller에서 시작해 Service·Mapper·SQL·테이블까지 실행 흐름을 근거와 함께 추적한다. '이 화면 데이터 어디서 조회돼?', '이 버튼 누르면 뭐가 실행돼?', '이 메뉴 코드 흐름 정리해 줘' 같은 요청에 사용."

**절차**
1. **범위 해석** — 시작점(JSP, 버튼, URL, 메서드, 테이블)을 정한다. 애매하면 해석을 한 줄로 밝히고 진행한다. 묻고 멈추지 않는다.
2. **인덱스 확보** — `.sistack/index/index.json`이 없거나 `source_revision`이 현재와 다르면 인덱서를 실행한다.
3. **복잡도 판단** — 화면 하나·버튼 하나 수준이면 단순, 메뉴 전체·여러 화면이 얽히거나 인덱스 경로가 20개 이상이면 복잡. 애매하면 단순.
4. **골격** — `query-index --from`(테이블에서 시작하면 `--to`)으로 골격을 만든다.
5. **확인·보완**
   - 단순: 골격의 각 연결을 소스에서 직접 확인한다. LIKELY·UNRESOLVED를 소스로 해소할 수 있으면 해소한다.
   - 복잡: 계층별(화면·JS / Controller·Service / SQL·DB) 읽기 전용 탐색자를 병렬로 실행한다. 각 탐색자는 `파일:라인`이 달린 요약만 돌려준다. Claude Code는 `Agent`, Codex는 `spawn_agent`, 서브에이전트가 없으면 같은 역할을 순차로 수행한다.
6. **숨은 경로 확인** — 인터셉터·필터·AOP, 공통 페이징, 공통코드 조회, 공통 예외 처리
7. **정리** — 출력 형식대로 작성하고 `.sistack/runs/<run-id>/`에 저장

**출력** (해당 없는 섹션은 생략)
- **개요** — 이 화면/기능이 하는 일 2~3문장
- **동작 흐름** — 텍스트 트리 + Mermaid. 각 연결에 CONFIRMED/LIKELY/UNRESOLVED
- **파일 위치** — 계층별 `파일:라인`
- **관련 테이블** — 읽기/쓰기 구분
- **함정** — 인터셉터가 넣는 값, 공통 페이징의 숨은 조건, `${}` 등 코드만 봐서는 놓치기 쉬운 것
- **확정 못 한 경로** — UNRESOLVED와 이유, 확인하려면 무엇이 필요한지

주석 달린 소스를 나열하지 말고, 처음 이 기능을 맡은 개발자가 구조를 머릿속에 잡을 수 있는 수준으로 쓴다.

**금지**
- 소스를 수정하지 않는다 (읽기 전용).
- 확인하지 않은 연결을 CONFIRMED로 쓰지 않는다.
- 존재하지 않는 클래스·메서드·테이블을 만들어내지 않는다. 0건이면 0건이라고 쓴다.

**사용 예시** — legacy-board 기준 입력·출력 예시 2개를 `references/`에 둔다 (단순 1, 복잡 1).

## eval

- `evals/trace/` 정답 5건에 대해 스킬을 실행하고 결과를 비교한다.
- 스킬 실행은 에이전트가 자기 자신에게 스킬을 적용하는 방식이 된다. 이 한계를 보고서에 명시한다.
- 비교 항목: 연결 누락, 과탐, 상태 불일치, 함정 섹션에 legacy-board 함정이 포함됐는지.
- 단순/복잡 분기가 각각 최소 1번 실제로 일어났는지 기록한다.
