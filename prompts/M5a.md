# M5a — si-docs 프로그램 목록·테이블 정의서

`AGENTS.md`, [M5 공통 범위](M5.md), `MILESTONES.md`를 따른다. 선행 조건은 M1·M4 완료와 xlsx/Playwright Node **통합 의존성 승인**이다. 승인 전 구현하지 않는다.

## 목표·범위

기존 M5 계획 중 문서 2종만 구현한다. 인덱스에서 프로그램 목록, 저장소 DDL 또는 사용자 제공 메타데이터 CSV에서 테이블 정의서를 추출해 사용자 xlsx 양식에 채운다. DB 직접 접속 금지. 화면 TC 실행·결과서는 M5b다.

| 문서 | 입력 | 확정하지 못한 값 |
|---|---|---|
| 프로그램 목록 | 화면·URL·Controller·Service·Mapper 인덱스와 소스 | 프로그램 ID/업무명 규칙은 사용자 입력, 추정 설명은 LIKELY |
| 테이블 정의서 | DDL·제공 CSV | DB 실존/운영 스키마를 추정하지 않으며 누락 속성 표시 |

## 구현 계약

- 단독 설치되는 `skills/si-docs/`에 프로그램 목록·테이블 정의서·양식 매핑 references와 실행 스크립트를 둔다. 상세 규칙은 references로 나눈다.
- 추출 표준 JSON(`schemas/docs/*.schema.json`)과 xlsx 채우기를 분리한다. 기본 양식은 2종이다.
- `extract-program-list`, `extract-table-spec`, `fill-template`은 Node.js 18 이상이며, 승인한 xlsx 의존성만 쓴다. 공통 코드는 sync-shared로 복사하고 단독 실행을 확인한다.
- 표준 JSON에는 파일:라인·CONFIRMED/LIKELY/UNRESOLVED와 원본 리비전을 남긴다. 확인 못 한 칸은 비우고 셀/보고서에 미확인을 표시한다. 값을 지어내지 않는다.
- 사용자 프로그램 ID 체계·양식은 외부 입력이다. 코드·샘플·보고서에 실제 회사/프로젝트 식별자를 고정하지 않는다.
- 매핑 파일은 template/sheet/header_row/start_row/columns/id_rule/fixed 등을 설명한다. 매핑이 없으면 헤더 기반 초안을 먼저 보여주고 확인 후 채운다.
- 병합 셀·서식·수식·다른 시트를 보존하고 원본을 덮어쓰지 않는다. 라이브러리가 보존하지 못하는 기능은 제한으로 보고한다.
- 생성 xlsx를 재읽어 행 수·필수 열·빈 칸·서식 보존을 검사한다. `.sistack/runs/<run-id>/`에 manifest/report/evidence를 남긴다.

## 검증

1. legacy-board로 기본 2종과 표준 JSON을 생성한다.
2. 병합 셀·서식·수식·다른 시트가 있는 합성 양식에 매핑한 뒤 보존을 재읽기로 검증한다.
3. 헤더 기반 매핑 초안과 미확인 칸 표시·목록 보고를 확인한다.
4. `validate-skills`, `sync-shared --check`, `npm test`를 실행한다.

## [GATE] 실제 양식

기본 2종과 매핑이 검토 가능한 상태가 되면 보고하고 멈춘다. 사용자가 민감정보를 제거한 실제 양식 1개와 경로를 지정한다. 참고 자료의 회사/프로젝트 식별자를 가져오거나 원문 양식을 저장소 샘플로 복사하지 않는다. 승인 후 실제 매핑·채우기와 원본 해시·서식 보존을 검증하고 손으로 보정한 매핑 항목 수와 한계를 보고한다. 양식 내용은 공개 보고에 인용하지 않는다.
