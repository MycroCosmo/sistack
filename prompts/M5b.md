# M5b — 화면/프로그램 단위 기능 테스트(TC) 결과서

`AGENTS.md`, [M5 공통 범위](M5.md)를 따른다. 선행 조건은 M5a 공통 추출/양식 기능과 통합 의존성 승인이다. 대상은 **legacy-board·legacy-board-thymeleaf의 전 화면**이다.

## 현장 규칙 일반화

- test-scenario-v2는 현장 규칙을 확인하는 참고 자료다. 원문·회사/프로젝트 식별자·현장 계정/경로/파일명 예시는 저장소에 복제하지 않는다. 문서·샘플·코드는 합성 값과 일반 규칙만 쓴다. 파일 경로가 확인되지 않으면 미확인으로 기록한다.
- 다른 대화에서 사용자가 공유한 v2 본문을 확인했다. 연결된 상세 가이드·실행 도구는 미제공이므로 구현/동작 검증 근거로 삼지 않는다. 교체된 v1 규칙은 적용하지 않는다. 현장 Python 도구·고정 엑셀 열 위치는 복제하지 않고 Node 구현과 양식 매핑으로 일반화한다.
- 여기서 단위테스트는 화면/프로그램 단위 기능 테스트다. M4의 Java 단위·Mapper 통합 결과와 분리한다.

## 1. 화면 기능 인벤토리 자동 생성

인덱서를 확장해 다음을 수집한다. 문자열 검색만으로 동작을 확정하지 않고 소스·연결 근거를 남긴다.

| 종류 | 필수 근거 |
|---|---|
| form | action·method·실제 id/name·입력·화면 소속 |
| 버튼·핸들러 | 버튼/이벤트 바인딩·핸들러·요청 연결 |
| AJAX | 요청 URL·HTTP 메서드·인자·콜백 연결 |
| data-url | 실제 속성과 이를 읽는 JS, 요청 연결 |
| 링크 | href와 이동 대상·요청 방법 |
| fragment | 선언·포함 지점·소속 화면·실제 기능 연결 |
| 단일 팝업 호출 | window.open/target 등 호출 근거·대상 |
| 숨김 필드 | 실제 name/id·폼 소속·값의 역할·요청 연결 |

각 항목에 안정적인 inventory_item_id, 종류, 소속 화면, 파일:라인, 상태·이유를 기록한다. 공통 fragment는 선언과 사용 화면을 구별한다. 전 화면의 기준에는 로그인/오류/공존 JSP도 포함하고, 독립 요청이 없는 fragment를 별도 화면으로 오인하지 않는다. 동적 URL·메서드·핸들러가 미확정이면 UNRESOLVED로 남긴다.

## 2. TC 초안과 1:1 대조

- 동작 인벤토리는 TC와 1:1로 연결한다. fragment 선언/포함·숨김 필드는 인벤토리에 남겨 누락 검사하되 독립 TC/엑셀 행을 만들지 않고 covered_by: <TC ID>로 화면 TC에 연결한다. 연결 대상 누락·중복·고아 TC를 검사한다. 추가 정상/경계/권한 TC는 보충 항목임을 표시한다.
- 인덱서가 아는 **기대 요청 URL·HTTP 메서드**를 TC 기대 결과에 자동 기입한다. 근거 상태와 파일:라인을 함께 보존한다. 독립 요청이 없는 구조 항목은 해당 없음, 연결을 못 찾은 경우는 미확정으로 구별한다. URL·메서드를 만들어 채우지 않는다.
- TC에는 업무명·사전 조건·계정/권한·입력·행동·기대 화면 결과·기대 요청·실행 유형·근거·증거 연결이 필요하다.
- 기대 화면 결과는 실제 소스/요구사항으로 확인한다. 인덱스만으로 없는 업무 규칙을 단정하지 않는다. 검증 정답은 독립 소스 대조 초안으로 만들고 AGENTS.md의 expected 승인 규칙을 따른다.

## 3. 실행 계약

| 실행 유형 | 방법·판정 |
|---|---|
| AUTO-API | 로그인 세션을 유지하는 HTTP 호출. 실제 로그인·권한·CSRF 흐름을 따르고 기대 URL/메서드/코드·업무 응답을 확인 |
| AUTO-UI | Playwright Node에서 이미 설치된 Chrome/Edge 사용. 실제 UI 동작 뒤 **기대 요청 URL·메서드·응답 코드와 화면 결과를 모두** 확인 |
| SKIP | **삭제·다운로드만**. 사유와 원래 요청/행동을 남기고 호출하지 않음 |

- Playwright 브라우저 다운로드·설치·기존 브라우저 교체 금지. 설치된 채널/경로와 버전을 탐지하고 실제 실행으로 호환성을 확인한다. 의존성 승인 전 Node 패키지도 설치하지 않는다.
- 생성·수정의 서버 반영은 AUTO-API로 확인하고, 버튼·단일 팝업 열림/선택·숨김 필드의 화면 동작은 AUTO-UI로 확인한다. 화면 항목을 API 결과만으로 대체하지 않는다. 권한 계정 미확보는 실행 전 선행조건이며 SKIP 사유가 아니다.
- selector 우선순위는 실제 id → name → 소스 href/th:href 해석값 → 해당 화면에서 유일한 소스 버튼/링크 텍스트 → 소스 form 범위의 유일한 버튼 텍스트다. 소스 값·파일:라인·실제 일치 건수·선택 근거를 JSON/TC 비고에 남긴다. 유일한 근거가 없으면 BLOCKED다. 추측 CSS/XPath·nth·임의 role/텍스트와 테스트 편의용 화면 소스 변경은 허용하지 않는다.
- AUTO-UI는 TC마다 스크린샷과 요청 기록을 보존한다. 요청 기록에는 예상/실제 URL·메서드·응답 코드·시각·증거 경로가 있어야 한다. 화면만 바뀌었거나 요청만 성공한 상태를 PASS로 세지 않는다. 증거 부족은 PARTIAL/BLOCKED로 남긴다.
- 실행 유형과 결과 상태를 구별한다. 삭제·다운로드 외 실패·선택자 부족·미지원 기능을 SKIP으로 숨기지 않는다. v0.2 범위 밖 항목도 인벤토리/대조에 남기고 실행 분모와 구별한다.
- 로컬 테스트베드에서만 실행한다. 운영 DB·배포/운영 서버 접근 금지. 쿠키·비밀번호·세션·CSRF·개인정보는 기록/이미지/엑셀에서 마스킹한다.
- 생성·수정한 데이터는 **삭제하지 않는다**. 자동 cleanup·rollback·DB 초기화·사본 폐기로 간접 제거하지 않는다. 입력 marker·생성 ID·수정 내역과 실행 사본을 보존한다. 보존 불가능한 실행 환경이면 시작 전에 BLOCKED와 대안을 보고한다.

## 4. 결과서의 현장 규칙

- 테스터는 **사용자가 지정한 계정 ID**다. 없으면 실행 전에 확인한다. 임의 이름·AI·자동화·도구명을 테스터로 채우지 않는다. 업무 결과/비고에 자동화 수행 문구를 삽입하지 않는다. 실행 유형·도구 버전은 증거 메타데이터에 남긴다.
- **1차/2차 열을 분리**한다. 1차 결과·날짜·계정·증거를 덮어쓰지 않는다. 2차는 별도 run/증거와 1차 원본 해시를 연결해 새 출력에 추가한다.
- **2차 여부가 불명확하면 실행·작성 전에 사용자에게 질문하고 답변을 기다린다.** 파일명·시각·v2 표기·빈 셀만으로 차수를 추측하지 않는다.
- FAIL의 근거 문의·오탐 확인 요청만으로 재수행하지 않는다. 먼저 보존 로그/화면으로 설명하고, 후속 실행은 명시된 차수와 승인 범위에 따른다.
- FAIL에는 제품 결함/자동화 오탐/미확정 분류와 근거를 남긴다. 선택자·세션·대기·환경 문제를 제품 결함으로 단정하지 않고, 자동화 오탐이라고 분류했다고 PASS로 바꾸지 않는다. 수정 후 확인은 승인된 후속 차수의 새 결과로 남긴다.
- 사용자 양식·원본·1차 열·서식·수식은 보존한다. 모르는 값은 빈 칸/미확인 표시하고 결과서 작성이 고객 검수 승인이라고 표현하지 않는다.

## 5. M4 보조 근거

M4 최종 `test-results.json`과 `schemas/test-results.schema.json`을 읽어 별도 **서버로직검증** 시트에 run-id·테스트·상태·파일을 연결한다. 2026-10-28 사용자 확정: 제공 양식의 기존 시트 구조·수식·드롭다운은 변경하지 않고 열도 추가하지 않는다. 화면 TC 자체의 실행 결과로 대체하지 않는다. 입력 위치는 [M4 종료 보고](../docs/m4-final-report.md)를 따른다.

제공 양식에서 BLOCKED는 결과 칸을 비우고 해당 차수 비고에 사유를 적으며 JSON 상태 BLOCKED를 유지한다. SKIP/PASS로 바꾸지 않는다. 실행 방식의 `수동` 값은 도구가 쓰지 않는다. 이는 M5b 구현 시 적용할 확정 규칙이며 M5a에서 결과서 작성·TC 실행을 시작하는 지시가 아니다.

## 7. 산출물과 의존성 GATE

- 인벤토리·TC 초안·1:1 대조·실행 결과·증거 메타데이터는 표준 JSON으로 저장하고 xlsx 채우기와 분리한다. 테스트 도구 세부사항은 업무 셀과 구별한다.
- `.sistack/runs/<run-id>/manifest.json`, report.md, evidence/ 및 원본 양식과 다른 출력 xlsx를 남긴다. raw 입력·비밀값은 보존 보고서에 옮기지 않는다.
- xlsx 라이브러리·Playwright Node의 후보·버전·라이선스·Node 요구사항·다운로드 없는 실행 방식을 비교해 **한 번에 승인 요청하고 멈춘다**. 사용자 승인 전 설치/lock 변경/구현 금지. 이 GATE는 M5a와 공유한다.

## 8. 검증·완료 기준

1. 두 테스트베드 **전 화면**을 독립 소스 대조 기준으로 열거한다. form/버튼·핸들러/AJAX/data-url/링크/fragment/팝업/숨김 필드 종류별 누락 수를 보고한다. 같은 인덱스 출력끼리 비교해 누락 0이라고 하지 않는다. 승인된 기준에서 **인벤토리 누락 0**이어야 한다.
2. 인벤토리↔TC 1:1 검사에서 누락·중복·고아 행을 검사하고, 알려진 요청 URL·메서드가 기대 결과에 들어가는지 확인한다.
3. 계정·차수·허용 환경·데이터 보존을 확인한 뒤 AUTO-API/AUTO-UI를 실행한다. SKIP은 삭제·다운로드만인지 검사한다. 유형별 PASS/FAIL/SKIP/PARTIAL/BLOCKED와 범위 밖을 분리한다.
4. AUTO-UI의 TC별 화면+요청 이중 증거, 실제 id/name 근거, 생성·수정 데이터 보존을 확인한다.
5. 실행 결과 xlsx를 생성·재읽기하고 행 수/필수 열/1차 보존/서식·수식·원본 불변을 확인한다. 사용자 양식은 M5a의 공통 매핑을 재사용하고 내용은 비공개다.
6. M3 학습 패치를 각각 임시 사본에 적용해 해당 TC가 **FAIL**인지 확인한다. 동일 TC를 정상/결함 사본에서 비교하고 테스트를 사후에 바꾸지 않는다. 로그 전용 Oracle처럼 실행 불가인 사례는 BLOCKED다. 삭제/다운로드 SKIP·v0.2 범위 밖·도구 오탐을 탐지 성공으로 세지 않는다. 학습 표본 크기와 가능한 사례 분모를 함께 보고한다.
7. 별도 서버로직검증 시트가 실제 승인된 M4 결과와 일치하고 화면 PASS를 대신하지 않는지 확인한다.
8. `validate-skills`, `sync-shared --check`, `npm test` 및 승인된 실제 양식 검증을 마친다. AGENTS.md 8절 형식으로 종료 보고한다.

구현 전에 필요한 의존성 승인을 받고 멈춘다. 실행 계정/차수가 없는 상태에서 질문을 생략하고 검증을 시작하지 않는다.

## 이번 실행의 승인·종료 기록 (2026-10-28)

의존성 GATE는 ExcelJS 4.4.0·playwright-core 1.64.1 사용자 승인으로 통과했다. 계정은 등록/수정/관리 admin, 조회 viewer이며 역할 선택 로그인에 대응한다. 신규 1차 보존 후 같은 TC를 승인 M3 학습 패치 사본에서 2차로 실행했다. 파일 H2·SQL 덤프·실행 사본을 보존하고 Chrome 우선/Edge 일부 교차를 수행했다. 인벤토리 기준 expected.json은 Ian의 별도 종류별 수동 집계 47/71 일치 확인으로 승인됐다. 팝업 0개는 실제 감지/실행 미검증이다.

최종 결과는 [M5b 종료 보고](../docs/m5b-final-report.md)를 따른다. BLOCKED 41건이 있어 전체 결과는 PARTIAL이며, 종료 보고 후 멈춘다. 과거 run의 초안 상태·1차·2차 원시 결과는 재작성하지 않는다.

## v3 보정 승인 (2026-10-29)

사용자 지시로 위 소스 선택자 우선순위와 구조 항목 covered_by 연결을 적용한다. v1/v2 원본·점수·기준은 그대로 보존하고 새 v3의 정상 1차 보존 후 같은 TC로 학습 패치별 2차를 실행한다. 인벤토리 누락 0을 유지하고 BLOCKED 사유 변화·TC 수 변화·탐지 결과를 별도 보고한다. 종료 후 M6는 시작하지 않는다.
