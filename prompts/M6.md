# M6 — 통합과 v0.1.0

`AGENTS.md`의 규칙을 따른다. 선행 조건: M2~M5 완료 기준 충족.

## 목표

1. 요구사항 하나를 기준으로 네 스킬이 이어지는지 확인한다.
2. 다른 SI 개발자가 설치해서 쓸 수 있는 상태로 정리한다.

사용자가 승인한 로그인 설정 분리·AI 없는 단일 CLI·공통 함수 수정안 분기와 통합 결함을 구현한다. v0.2 기능은 추가하지 않는다.

## 1. 통합 시나리오

**요구사항:** `REQ-001` "게시판 목록에서 작성자로 검색하면 오류가 난다"

`evals/integration/REQ-001/`에 버그 패치와 증상을 준비한다 (M3 케이스 재사용 가능, 단 작성자 검색과 관련된 것이어야 한다).

legacy-board 임시 복사본에서 다음을 순서대로 실행한다. 모든 run에 `request_id: "REQ-001"`을 넣고 `parent_run_ids`로 앞 단계를 연결한다.

1. `si-trace` — 목록 화면의 작성자 검색 흐름 파악
2. `si-debug` — 증상·로그로 원인 분석
3. 수정 — si-debug 수정안 적용 (시나리오 안에서는 사용자 승인으로 간주하고, 보고서에 그렇게 적는다)
4. `si-unit-test` — 회귀 테스트 작성. 수정 전 코드에서 실패, 수정 후 통과를 둘 다 실행해 기록
5. `si-docs` — 프로그램 목록 + 화면 TC 결과서 1차/2차 생성. M4/JUnit 결과는 별도 서버로직검증 시트의 보조 근거로만 연결

`scripts/run-integration.mjs`로 이 시나리오를 재실행 가능하게 만든다 (스킬 실행 부분은 에이전트가 수행하더라도, 준비·검증 부분은 스크립트로).

**검증**
- 모든 manifest가 스키마 검증 통과
- `parent_run_ids` 체인이 1 → 5로 끊기지 않음
- 단위테스트 결과서의 테스트가 4번에서 실제 실행된 테스트와 일치
- `scripts/trace-request.mjs REQ-001`이 요구사항 → 각 run → 증거 파일 목록을 출력 (향후 PL/PM 연계의 출발점)

## 시작 전 사용자 확정 범위 (2026-10-29)

이 절을 기존 문구와 충돌할 때 우선 적용하고, 구현 전 프롬프트 변경을 먼저 커밋한다.

1. REQ-001 작성자 검색 오류: si-trace → si-debug → 승인된 시나리오 사본 수정 → si-unit-test(수정 전 FAIL/후 PASS) → si-docs(프로그램 목록 + 화면 TC 1차/2차)를 request_id/parent_run_ids로 잇는다. 원본·기존 마일스톤 결과는 보존한다.
2. sistack-docs.json의 auth로 login_url, 필드명, 성공 판정 URL/요소, 계정 ID를 정의한다. 비밀번호는 환경 변수 참조만 허용하고 설정 파일/로그/결과서에 저장하지 않는다. 기존 legacy-board 역할 선택 로그인도 설정으로 재현하며 기능 실행의 인증 하드코딩을 없앤다.
3. npx로 실행하는 단일 sistack 진입점: trace / debug-parse / unit-plan / docs program-list / docs table-spec / docs tc. full / structure-only / no-ai 출력 모드를 구별하고 명시 실행 승인 없는 CLI는 읽기/계획만 수행한다. 외부 AI 호출/키 설정을 요구하지 않는다.
4. si-debug 수정이 여러 호출자의 공통 함수에 걸리면 국소/공통 수정안을 함께 제시하고 인덱서 --to의 다른 호출자 목록을 첨부한다. 기본 추천은 국소 수정이다.
5. docs/evidence 대용량 원본/아카이브를 별도 로컬 릴리스 보관 폴더로 옮기고 무결성 해시 목록만 커밋한다. 기존 증거는 삭제/재작성하지 않는다. 과거 Git 이력은 재작성하지 않고 잔존 대용량/식별자도 점검·보고한다. buffers@0.1.1 라이선스는 배포 README/원출처로 확인하고 출처·근거를 기록한다. 회사·개인 식별자 및 비밀값 검사를 수행한다.
6. README 설치/스킬4개 예시/AI없는CLI/보안/pstack 관계, docs/pstack-mapping.md, CONTRIBUTING.md, CHANGELOG.md, NOTICE를 정리한다.
7. AGENTS.md에 전역 스타일 규칙과 충돌 시 이 문서 우선 한 줄을 추가한다.
8. Claude Code 실제 로딩과 Codex 자동 활성화 남은 2문항은 수동 절차를 갱신하고 BLOCKED로 명시한다. CLI 설치 검증을 실제 세션 로딩/활성화 성공으로 대체하지 않는다.
9. 검증 후 로컬 태그 v0.1.0만 생성한다. push/원격 생성/패키지 배포 금지. 종료 보고 후 멈춘다.
