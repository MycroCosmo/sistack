# M0 — 저장소 기반

`AGENTS.md`의 규칙을 따른다. 이 마일스톤에서는 스킬 기능을 구현하지 않는다.

## 목표

이후 모든 마일스톤이 올라설 저장소 뼈대, 검증 도구, 테스트베드를 만든다.

## 먼저 할 일

1. `git status`와 현재 파일 구조를 확인한다.
2. 다음 공식 문서를 읽고, 확인한 내용을 `docs/decisions.md`에 짧게 기록한다.
   - Agent Skills 명세: https://agentskills.io/specification (frontmatter 필드, name 규칙, 길이 제한)
   - Codex 스킬 문서: https://developers.openai.com/codex/skills (설치 경로, 호출 방식, `agents/openai.yaml`)
   - Claude Code 스킬 문서 (설치 경로, frontmatter 확장 필드)
   - pstack README와 `skills/how/SKILL.md` (구조 참고)
3. 문서 내용이 `AGENTS.md`와 다르면 문서를 따르고, 차이를 보고한다.

## 작업

### 1. 저장소 구조

```text
sistack/
├── AGENTS.md  MILESTONES.md  README.md  LICENSE  NOTICE  package.json  .gitignore
├── prompts/
├── skills/                  # 스킬 원본 (M2~M5에서 채움)
├── lib/
│   └── mask/                # 마스킹
├── schemas/
├── scripts/
├── examples/
│   └── legacy-board/
├── evals/
│   ├── debug/cases/
│   └── private/             # gitignore
└── docs/
    ├── decisions.md
    └── limitations.md
```

- `LICENSE`: MIT
- `.gitignore`: `evals/private/`, `.sistack/`, `node_modules/`, 테스트베드 클론 폴더, 빌드 산출물

### 2. 검증 도구

- `schemas/manifest.schema.json`: `AGENTS.md` 4절 필드 기준. JSON Schema 검증 라이브러리를 쓸지, 필요한 범위만 직접 검증할지 결정하고 기록한다.
- `scripts/validate-manifest.mjs <path>`
- `scripts/validate-skills.mjs [skills-dir]`: 명세의 name 규칙, 폴더명 일치, description 존재·길이, 본문 300줄 이하, 참조한 `references/`·`scripts/` 파일 존재 여부
- `scripts/sync-shared.mjs`: `lib/`의 지정 모듈을 각 스킬 `scripts/lib/`로 복사. `--check` 옵션은 차이가 있으면 실패
- `scripts/install.mjs --target codex|claude --scope repo|user [--dest <dir>]`: 스킬 복사 설치. 기존 파일이 있으면 덮어쓰기 전에 목록을 출력하고 `--force` 없이는 중단
- `lib/mask`: 주민등록번호, 휴대폰·전화번호, 이메일, 카드·계좌번호 패턴, `password=`·`secret`·`token` 류 설정값, JDBC URL의 비밀번호. 단위 테스트 포함 (오탐·미탐 사례 모두)
- `npm test`: 위 도구들의 단위 테스트 + `validate-skills` + `sync-shared --check`

### 3. 테스트베드: legacy-board

`examples/legacy-board/`에 **빌드·실행 가능한 소형 레거시 게시판**을 만든다. 실제 한국 SI 프로젝트의 모양을 따른다.

기술 구성:
- Maven, Java 8 소스 레벨 (JDK 11/17에서 `--release 8`로 빌드되게)
- Spring MVC 5.3 (XML 설정 + 어노테이션 혼용), JSP + JSTL + jQuery
- MyBatis 3.5, Mapper 인터페이스와 XML 혼용, 일부는 `SqlSessionTemplate` + 문자열 sqlId 호출(DAO 방식)
- 운영 DB는 Oracle을 가정한 SQL 스타일, 테스트는 H2 (Oracle 호환 모드)
- JUnit 4 + Mockito (레거시에서 흔한 조합)

기능:
- 게시판 목록(검색 조건: 제목/작성자/기간, 공통 페이징), 상세, 등록, 수정, 삭제
- 공통코드 테이블 조회 (게시판 분류)
- 로그인 세션 체크 인터셉터, 권한별 메뉴 접근
- `CharacterEncodingFilter`, 공통 예외 처리

반드시 포함할 함정 (M1·M2 검증용):
- JS에서 문자열 조합으로 만든 URL
- 서로 다른 클래스의 같은 이름 메서드
- 여러 화면이 쓰는 공통 페이징 클래스와 `<include refid>`로 공유되는 SQL 조각
- 정렬 컬럼에 `${}` 사용
- 주석 처리된 옛 호출 코드
- 인터셉터에서 세션 값을 request에 넣어 Controller가 쓰는 구조

규칙:
- 코드에 정답 힌트(“여기가 함정” 같은 주석)를 넣지 않는다. 함정 목록은 `evals/legacy-board-traps.md`에만 기록한다.
- 원본 코드에는 버그를 넣지 않는다. 버그는 M3에서 패치 파일로 관리한다.
- 기본 Service 몇 개에 대한 기존 테스트를 1~2개만 둔다 (테스트가 거의 없는 현실 반영).
