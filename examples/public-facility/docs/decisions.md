# 구현 결정

2026-10-29. 새 프로젝트 구현·검증에 대한 사용자의 요청 범위에서 결정했다.

| 결정 | 근거와 영향 |
|---|---|
| theHands는 업무 계층만 참고 | 구현 전에 si-trace로 Controller → Service → Mapper → SQL을 대조했다. 참고 소스의 외부 공개·복제 없이 역할 분리를 새 업무에 적용했다. |
| Spring MVC XML + Thymeleaf | 사용자가 Thymeleaf 실습을 선택했다. SIStack 기존 예제의 POM과 로컬 실행 환경을 재사용해 새 의존성을 추가하지 않았다. Spring Boot를 그대로 재현한 것은 아니다. |
| 신청·이력 보존 | 승인·반려·취소는 상태 변경과 이력 추가로 처리한다. 참고 업무의 반려 시 연관 데이터 삭제 정책을 가져오지 않았다. |
| 시설 단위 행 잠금 | 같은 시설의 신청·운영 변경·상태 변경을 직렬화해 시간 중복과 운영 중지 경합을 제어한다. 잠금은 단일 로컬 H2에서 검증했으며 타 DB 호환성은 확인하지 않았다. |
| 파일 H2와 테스트 메모리 H2 분리 | 로컬 앱은 재시작 후 보존하고 테스트는 격리한다. 기존 H2 의존성의 test scope와 Jetty useTestScope를 유지한다. 운영 DB 설정은 제공하지 않는다. |
| 생성기 한계는 원본 기록 유지 | 자동 계획 29건/생성 0건을 보존했다. 앱의 정상 wildcard import를 생성기에 맞추려고 고치지 않고, 업무 테스트 19건을 에이전트가 보충했다. |
| 문서 미확인 값은 공란 | 사용자가 승인한 두 기본 양식에 확인 가능한 소스·DDL 값만 작성했다. 문서 PARTIAL을 앱 테스트 실패로 혼동하지 않는다. |

추가 외부 의존성 없음. 사용 버전과 전이 의존성은 `pom.xml` 및 Maven 저장소를 기준으로 하며, 이 문서는 최신 보안 버전 검토나 운영 적합성 평가가 아니다.
