# 구현 결정

- 사용자는 Thymeleaf 화면과 공공시설 사용 신청·승인·관리 주제를 선택했다. theHands는 신청 심사 및 계층 분리의 참고 대상으로만 읽었다. 원본 소스·DB 접속 설정·계정·정적 자산을 복제하지 않았다.
- 기존 `legacy-board-thymeleaf`의 Maven/XML 실행 구성을 재사용해 설치 비용을 줄였다. 새 라이브러리나 새 버전은 도입하지 않았다. 별도 npm 의존성 없이 Node 표준 라이브러리로 실행기를 만들었다.
- 새 프로젝트는 `examples/public-facility` 내부에서 자체 Maven/npm 명령으로 동작하며 SIStack 라이브러리를 앱에서 import하지 않는다. 기존 테스트베드와 평가 정답은 변경하지 않는다.
- 시설 단위 `SELECT FOR UPDATE`와 같은 트랜잭션 안의 중복 검사·저장으로 동시 신청을 직렬화한다. 실습에서는 시설 수와 트래픽이 작으므로 시간대별 잠금보다 단순한 방식을 택했다. H2 실측이며 다른 DB의 잠금 특성은 별도 검증 대상이다.
- 신청자 필드는 세션에서 결정하고 상태는 서비스에서 정한다. 화면 숨김 값에 권한이나 상태 결정을 맡기지 않는다. CSRF와 역할별 객체 접근 검증을 서버에서 수행한다.
- 반려·취소 시 신청 행을 삭제하지 않는다. 상태 변경과 이력을 원자적으로 저장한다. 반려·취소된 시간대는 다시 사용할 수 있다.
- 메모리 H2와 허용 목록 역할 로그인을 사용한다. 시작·반복 실습이 쉬운 구성이며 실제 인증·운영·데이터 영속화를 제공하지 않는다. 종료 시 데이터 소멸을 README에 명시한다.
- 기존 의존성 재사용은 보안 업데이트 적합성이나 운영 배포 승인을 뜻하지 않는다. 로컬 실습용으로 127.0.0.1:8092에만 바인딩한다.
- 정상본에 의도적인 버그나 정답 힌트를 심지 않았다. 후속 변경 요청은 요구사항 문서에 미구현으로 구분했다.
