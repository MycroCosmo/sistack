# 온마을 시설관리 요구사항

가상의 공공기관 업무다. 사용자 선택으로 정한 실습 범위이며 법령·실제 기관 규정이 아니다.

| ID | 요구사항 | 확인할 사용자 동작 |
|---|---|---|
| FAC-001 | 신청자·담당자·관리자 역할 구분 | 다른 신청자의 상세와 이력 접근은 403, 신청자는 승인 불가 |
| FAC-002 | 시설 위치·정원·운영 상태 조회 | 운영 중인 시설만 신청 목록에 노출 |
| FAC-003 | 내일부터 90일 이내 사용 신청 | 당일/과거/91일 이후/잘못된 날짜 거부 |
| FAC-004 | 운영시간 09:00~18:00, 1회 최대 4시간 | 시작≥종료, 운영시간 밖, 4시간 초과 거부 |
| FAC-005 | 인원·목적 검증 | 인원 1~시설 정원, 공백 제외 목적 1~300자 |
| FAC-006 | 접수·승인 시간의 중복 신청 방지 | 겹치면 거부, 앞 신청 종료=다음 시작은 허용 |
| FAC-007 | 동시 요청에서도 중복 방지 | 같은 시설 행 잠금 이후 확인·저장, 같은 슬롯 동시 요청은 1건만 성공 |
| FAC-008 | 담당자의 승인·반려 | 접수 상태만 심사, 신청자 본인의 직접 승인 금지, 반려 사유 필수 |
| FAC-009 | 신청자 본인 취소 | 접수/승인 상태, 사용일 전, 취소 사유 필수. 관리자 대리 취소 불가 |
| FAC-010 | 변경 이력 보존 | 변경자·이전/다음 상태·사유·시각 저장. 이력 저장 실패 시 상태도 롤백 |
| FAC-011 | 시설명·목적·상태 검색과 페이징 | 역할별 범위 유지, 10건씩 최신 신청순 조회 |
| FAC-012 | 시설 운영 중지·재개 | 관리자만 변경. 중지는 신규 접수와 대기 신청 승인을 차단하고 기존 승인은 보존 |
| FAC-013 | 업무 집계 | 신청자는 본인, 담당자/관리자는 전체 신청의 상태별 건수 |
| FAC-014 | 변경 요청 보호 | 로그인 세션·CSRF 검사, 화면 입력의 신청자/상태 위조를 저장하지 않음 |

상태 전이는 `접수 → 승인 / 반려 / 취소`, `승인 → 취소`다. 반려·취소는 종료 상태이며 재신청은 새 신청으로 등록한다. 심사와 취소는 사용일 당일부터 차단한다. 중복 판정은 `기존 시작 < 신규 종료 AND 기존 종료 > 신규 시작`이다.

DB는 `facility`, `booking`, `booking_history` 3개 테이블이다. 사용자 계정은 외부 사용자 테이블 대신 실습용 서버 허용 목록으로 제공한다.

## 후속 실습용 변경 요청 — 아직 구현하지 않음

1. **CR-001**: 운영시간을 08:00~20:00으로 바꾸되 4시간 제한을 유지한다. 화면 입력 범위와 서버 검증, 경계 테스트를 함께 검토한다.
2. **CR-002**: 승인 목록에 사용일 범위 검색을 추가한다. 기존 신청자 범위·키워드·페이징 조건을 보존한다.
3. **CR-003**: 관리자가 사용 중지 사유를 입력하고 운영 변경 이력을 남기도록 한다. DDL·화면·권한·문서 변경을 함께 검토한다.

위 항목은 사용자가 다음 작업을 선택하기 위한 요청 예시이며 자동으로 개발하지 않는다. 현재 정상본에 의도적인 결함은 넣지 않았다.
