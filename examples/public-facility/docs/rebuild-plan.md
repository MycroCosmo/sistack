# 스킬 기반 재구현 계획

2026-10-29. 사용자가 이전 프로젝트를 삭제하고 SIStack 스킬을 사용해 다시 만들도록 요청했다. 이전 구현은 삭제 커밋으로 분리했다. 신규 구현 코드는 아래 분석 후 작성한다.

1. **si-trace — 구현 전 완료**: theHands의 신청 목록 경로를 prepare → 소스 대조·연결 보완 → finish로 분석했다. run `facility-reference-20261029`, 상태 PARTIAL. 중첩된 호출의 자동 수집 누락을 원문으로 보완했고 프로필/권한 실행 미확인은 유지했다. 상세 증거는 참고 프로젝트 내부 `.sistack`에 보존한다.
2. **분석에 따른 구현**: Controller는 입력/세션/화면, Service는 권한·시간·상태 전이, Mapper는 조건부 조회·저장으로 분리한다. 참조 프로젝트의 반려 시 관련 데이터 삭제 정책은 가져오지 않고 신청 및 상태 이력을 보존한다. 기존 선택인 공공시설 업무·Thymeleaf를 유지한다.
3. **si-unit-test — 구현 중 적용**: 실제 POM 탐지, 소스 기반 자동 계획/테스트 생성, 생성 불가 항목 기록, 에이전트의 업무 테스트 보충, 공식 실행기로 표준 test-results 생성, 별도 사본의 변이 탐지 검증을 수행한다. 생성기와 에이전트 작성 수를 구분한다.
4. **si-debug — 실제 오류가 발견될 때 적용**: 최초 실패와 원인을 보존하고 prepare/diagnosis/finish 후 수정한다. 적용 사례를 만들기 위한 의도적인 오류 주입은 하지 않는다. 약한 테스트 검사는 별도 변이 실험으로 구분한다.
5. **si-docs — 산출물 작성**: 프로그램 목록·테이블 정의서 원본 JSON, 기본 양식·매핑 초안, 매핑 확인 후 채우기·재읽기·manifest/report를 만든다. 화면 TC는 별도의 계정·차수·실행 계획이 필요하므로 이 두 문서와 구분한다.

범위: 시설 조회/운영 관리, 신청·검색·페이징, 승인·반려·본인 취소, 중복 시간·정원·기간 검증, 세션/CSRF, 변경 이력. 기존 버전의 라이브러리만 재사용한다. 소스 복원 후 스킬을 실행한 것으로 포장하지 않는다.

검증되지 않은 연결·자동 생성 한계·문서 미확인 값은 그대로 남긴다. 합성 프로젝트 자체 검증을 독립 평가나 고객 검수라고 표현하지 않는다.
